# Data Model: Production Readiness

## Validation Workflow

**Purpose**: The full release-readiness run across quality, tests, evals,
security, build, smoke, artifact, tracing, and documentation gates.

**Fields**:

- `run_id`: unique workflow run identifier.
- `trigger`: local, pull request, push, or manual.
- `git_sha`: source revision when available.
- `started_at`: workflow start timestamp.
- `completed_at`: workflow completion timestamp.
- `gates`: ordered list of quality gates.
- `overall_status`: pass or fail.
- `artifacts`: generated report and log artifact references.

**Validation rules**:

- Overall status is pass only when every required gate passes.
- Gate skipping is treated as failure unless explicitly marked optional in this
  phase plan; Phase 10 gates are required by default.
- CI must not require real paid API credentials.

## Quality Gate

**Purpose**: One pass/fail validation step.

**Fields**:

- `gate_id`: stable identifier, such as `lint`, `format`, `type_check`,
  `tests`, `classifier_eval`, `rag_eval`, `redaction`, `static_secret_grep`,
  `previous_green_diff`, `docker_build`, `smoke`, `artifact_hash`,
  `vault_boot`, `model_boot`, `threshold_boot`, `tracing_boot`, `tracing`, or
  `docs`.
- `command`: command or script invoked.
- `required`: whether the gate blocks release.
- `timeout_seconds`: bounded runtime where applicable.
- `status`: pass, fail, or skipped.
- `failure_code`: stable failure code when failed.
- `summary`: short safe explanation.
- `artifacts`: output files generated by the gate.

**Validation rules**:

- Required gates cannot be skipped.
- Failure summaries must not contain raw secrets or sensitive payloads.
- Gate commands must be runnable locally or in CI with documented prerequisites.

## Evaluation Thresholds

**Purpose**: Committed non-zero thresholds used by eval gates.

**Fields**:

- `classifier_accuracy_min`: minimum classifier accuracy.
- `classifier_macro_f1_min`: minimum classifier macro-F1.
- `rag_hit_at_5_min`: minimum retrieval hit@5.
- `rag_mrr_at_10_min`: minimum retrieval MRR@10.
- `rag_faithfulness_min`: minimum faithfulness score where available.
- `rag_answer_relevancy_min`: minimum answer relevancy where available.
- `enabled`: threshold gate enabled flag that must be true for committed
  thresholds.

**Validation rules**:

- Thresholds must be enabled, present, numeric, finite, and greater than zero.
- Missing, disabled, zero, negative, or malformed thresholds fail the workflow
  and startup validation.
- Threshold changes require `docs/decisions.md` or `docs/evals.md`
  explanation.

## Evaluation Result

**Purpose**: Current eval metrics and pass/fail comparison for one eval track.

**Fields**:

- `track`: classifier or rag.
- `dataset_id`: golden set or local fixture identifier.
- `artifact_id`: model, index, or system artifact identifier.
- `metrics`: metric name to numeric value mapping.
- `thresholds`: thresholds used for comparison.
- `passed`: boolean result.
- `failures`: list of failing metrics.
- `latency`: optional latency summary.

**Validation rules**:

- Metrics required by thresholds must be present.
- Below-threshold metrics fail the track.
- Results are deterministic for the committed compact gate inputs.

## Evaluation Report

**Purpose**: Combined `eval_report.json` generated by the validation workflow.

**Fields**:

- `run_id`: validation workflow run identifier.
- `timestamp`: report timestamp.
- `classifier`: classifier evaluation result containing `accuracy`,
  `macro_f1`, `per_class_f1`, and threshold-aligned pass/fail data.
- `rag`: RAG evaluation result containing `hit_at_5`, `mrr_at_10`,
  `faithfulness`, `answer_relevancy`, and threshold-aligned pass/fail data.
- `storage`: report storage destination metadata with `bucket` and `key`.
- `passed`: final report pass/fail.
- Optional safe metadata may include schema version, git SHA, gate summaries,
  and previous-green comparison details as long as the required fields remain
  stable and documented by the contract.

**Validation rules**:

- Report is generated for every successful validation run.
- CI reports are stored in MinIO. MinIO-compatible local paths are allowed only
  for dev/test adapter runs.
- Report diffing against the previous green build must be recorded when a
  previous green report exists.
- Report must not contain raw secrets, raw prompts, raw memory values, or
  sensitive provider credentials.

## Previous Green Eval Report

**Purpose**: Last successful CI eval report used to detect regressions beyond
minimum thresholds.

**Fields**:
- `report_ref`: MinIO object reference or safe artifact identifier.
- `git_sha`: commit associated with the previous green report.
- `timestamp`: previous report timestamp.
- `classifier_metrics`: comparable classifier metrics.
- `rag_metrics`: comparable RAG metrics.
- `comparison_result`: pass/fail diff summary.
- `regressions`: list of metrics that regressed beyond allowed tolerance.

**Validation rules**:
- Missing previous green report is allowed only for the first run and must be
  reported explicitly.
- Malformed previous green reports fail the diff gate after the first successful
  stored report exists.
- Diff output must not contain raw prompts, chunks, memory values, or secrets.

## Redaction Leak Probe

**Purpose**: Fake secret-like input used to prove redaction works.

**Fields**:

- `probe_id`: identifier for the leak test.
- `fake_secret_value`: fake API key or credential string.
- `targets_checked`: logs, traces, memory, audit, captured output.
- `leak_found`: boolean.
- `redacted_form`: expected redacted replacement.

**Validation rules**:

- Probe value must be fake and safe to commit in tests.
- Raw fake secret value appearing in any target fails the workflow.
- Captured failure output must avoid reprinting the raw fake secret.

## Static Secret Pattern Check

**Purpose**: Static scan for unsafe secret-like strings in committed or generated
review outputs.

**Fields**:
- `patterns`: checked pattern labels, including `sk-` and `password`.
- `targets_checked`: files or artifact directories scanned.
- `matches_found`: count of unsafe matches.
- `allowlist_ref`: safe allowlist reference for false positives.
- `passed`: whether no unsafe matches were found.

**Validation rules**:
- Unsafe `sk-` or password-like matches fail the workflow unless explicitly
  allowlisted with a safe reason.
- Failure output reports path and pattern label without exposing real secret
  values.

## Model Artifact Integrity Check

**Purpose**: Verification that model artifacts match their model cards.

**Fields**:

- `artifact_path`: path to required artifact.
- `model_card_path`: path to model card.
- `expected_sha256`: hash recorded in the model card.
- `actual_sha256`: computed artifact hash.
- `exists`: whether artifact exists.
- `passed`: whether hash validation succeeded.

**Validation rules**:

- Missing required artifact fails validation.
- Missing, malformed, or mismatched SHA-256 fails validation.
- Hash mismatch messages include paths and safe hash prefixes, not full secrets.

## Startup Failure Check

**Purpose**: Negative validation proving the app fails closed.

**Fields**:

- `case_id`: vault_unreachable, vault_missing_secret, model_artifact_missing,
  model_hash_mismatch, tracing_misconfigured, eval_threshold_zero, or
  eval_threshold_disabled.
- `configuration`: safe test configuration label.
- `expected_failure_code`: stable failure code expected.
- `observed_failure_code`: actual failure code.
- `passed`: whether the expected failure occurred.

**Validation rules**:

- A startup success in a negative case fails the check.
- Failure output must be structured and explainable.
- Failure output must not contain raw secrets.

## Tracing Config Validation

**Purpose**: Verification that tracing is configured enough for request, LLM,
tool, and RAG observability.

**Fields**:

- `enabled`: whether tracing is enabled for the test profile.
- `backend`: selected tracing backend label.
- `endpoint_configured`: whether endpoint or sink is configured.
- `request_id_supported`: whether request IDs are propagated.
- `trace_id_supported`: whether trace IDs are propagated.
- `passed`: validation result.

**Validation rules**:

- Missing required tracing sink or identifiers fails when tracing is enabled.
- Fake/local tracing sinks are acceptable for CI.
- Validation does not require a paid tracing provider.

## Stack Smoke Test Run

**Purpose**: Full production-functional Docker Compose stack validation.

**Fields**:

- `compose_profile`: profile used for smoke test.
- `services_started`: service names started.
- `health_endpoint`: endpoint tested.
- `status_code`: observed health response code.
- `duration_seconds`: elapsed smoke-test time.
- `passed`: whether health check passed.

**Validation rules**:

- Smoke test starts the full production-functional stack required by the spec,
  including the model server.
- Health endpoint must be reached before timeout.
- Logs collected for failure must be safe for CI output.

## Documentation Set

**Purpose**: Required final review and operations documentation.

**Fields**:

- `readme_path`: README path.
- `arch_path`: architecture documentation path.
- `decisions_path`: decisions documentation path.
- `runbook_path`: runbook path.
- `evals_path`: eval documentation path.
- `security_path`: security documentation path.
- `required_sections`: section names expected in each document.
- `complete`: whether all docs satisfy the required section check.

**Validation rules**:

- Missing document fails documentation validation.
- Missing required section fails documentation validation.
- `docs/decisions.md` must include numeric evidence for classifier, embedding,
  chunking, retrieval weighting, reranking, memory type, and tracing backend.

## State Transitions

```text
Validation Not Started -> Gate Running -> Gate Passed -> Next Gate
Validation Not Started -> Gate Running -> Gate Failed -> Workflow Failed
All Required Gates Passed -> Report Generated -> Report Stored -> Workflow Passed
Report Generated -> Storage Failed -> Workflow Failed
Report Generated -> Previous Green Diff Failed -> Workflow Failed
Threshold Missing, Disabled, Or Zero -> Workflow Failed
Secret Leak Detected -> Workflow Failed
Static Secret Pattern Detected -> Workflow Failed
Startup Negative Case Boots Successfully -> Workflow Failed
```
